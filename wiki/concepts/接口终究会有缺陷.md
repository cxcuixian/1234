# Interfaces Inevitably Have Defects

## Definition

Interfaces inevitably have defects expresses skepticism toward treating interfaces or abstractions as complete substitutes for their underlying implementations. It emphasizes that an interface may conceal missing capabilities, constraints, or failure modes, whereas complete code can be reproduced and adapted according to one’s own ideas.

## Key Characteristics

- Challenges the assumption that an interface fully represents the underlying implementation.
- Highlights hidden limitations, unavailable capabilities, and concealed failure modes.
- Distinguishes abstraction-level access from control over complete, reproducible code.
- Is relevant to the contrast between [[Vibe Coding]] and [[Code Engineering]].
- Encourages examination of implementation details rather than relying exclusively on surface-level interfaces.

## Applications

- Evaluating APIs, libraries, platforms, and other abstraction layers.
- Identifying risks when an interface hides important implementation constraints.
- Comparing rapid experimentation through [[Vibe Coding]] with disciplined [[Code Engineering]].
- Deciding when [[Complete Code]] is preferable to an externally provided interface.
- Assessing whether a system can be reproduced, modified, or debugged independently.
